# Smart Logistics final demonstration project

This folder contains the complete STM32 firmware and a no-build local dashboard. Both use one event vocabulary and one JSON telemetry schema: `NORMAL`, `IMPACT`, `VIBRATION`, `TAMPER`, `HIGH_TEMP`, `HIGH_HUM`, and `MANUAL`.

## 1. Hardware wiring

| Module | STM32F103C8T6 connection |
|---|---|
| USB-to-TTL for dashboard/debug | PA2 TX → adapter RX, PA3 RX ← adapter TX, GND ↔ GND. Do **not** connect adapter VCC. |
| NEO-6M GPS | GPS TX → PA10, GPS RX → PA9, common GND; Serial1 at 9600 baud. |
| MPU6050 | SDA → PB7, SCL → PB6, AD0 → 3.3 V (address 0x69), VCC → 3.3 V, GND. |
| DS3231 | SDA → PB7, SCL → PB6, address 0x68, common GND. |
| Optional 20×4 I2C LCD | SDA → PB7, SCL → PB6, address 0x27, common GND, module-rated VCC. |
| DHT11 | DATA → PB5, VCC → 3.3 V, GND. Add the normal data pull-up if using a bare sensor. |
| microSD | CS → PA4, SCK → PA5, MISO → PA6, MOSI → PA7, common GND. Use a 3.3 V-safe module. |
| SW-420 | DO → PB15, common GND. Default firmware polarity is active-low. |
| Reed switch | PA1 → switch → GND. Closed/magnet present is LOW (safe). |
| Buzzer | Signal → PB0, common GND. Use a transistor driver if the buzzer current exceeds GPIO limits. |
| LEDs | PB1 green, PB10 blue, PB11 red → one 330 Ω resistor per LED → LED → GND. |
| Buttons | PB13 and PB14 → separate pushbuttons → GND. Internal pull-ups are enabled. |

## 2. Arduino IDE preparation

1. Install **Arduino IDE 2.x** and **STM32 MCU based boards by STMicroelectronics 3.0.0**.
2. Install these libraries with Library Manager: **Adafruit MPU6050**, **Adafruit Unified Sensor**, **DHT sensor library**, **RTClib**, **TinyGPSPlus**, and **LiquidCrystal I2C**.
3. If no LCD is connected, open `firmware/SmartLogistics.ino` and change `#define USE_LCD 1` to `0`; then the LCD library is not required.
4. Select **Generic STM32F1 series** → **BluePill F103C8 / STM32F103C8T6**, upload method **STM32CubeProgrammer (SWD)**, and the matching optimization/default settings for STM32 core 3.0.0.
5. Connect ST-LINK: SWDIO, SWCLK, GND, and the appropriate board power connection. Open `firmware/SmartLogistics.ino`, verify, and upload.
6. The debug port is exactly `Uart DebugSerial(PA3, PA2)` at 115200 baud. It does not use `Serial2`.

At boot, the three LEDs and buzzer run a short self-test. Green then means normal, red means an active event, and blue briefly flashes after a successful telemetry write. `TELEM.CSV` and `EVENTS.CSV` are created on the SD card.

## 3. Run the dashboard on Windows

1. Install Python 3 if `py`/`python` is not already available.
2. Double-click `START_DASHBOARD.bat`. Keep its black command window open during the demo. It opens `http://localhost:8000`.
3. Use current **Google Chrome** or **Microsoft Edge**. Web Serial is not supported by Firefox or Safari.
4. Close Arduino Serial Monitor and every other program using the USB-to-TTL COM port.
5. Click **Connect STM32**, select the USB-to-TTL COM port, and approve it. Live JSON packets update the cards, graph, health panel, and timeline.
6. If hardware is not connected, click **Demo stream**. To replay the SD log, click **Import CSV** and select `TELEM.CSV`.

The dashboard can be opened directly as a file for CSV/demo mode, but Web Serial should be run from localhost as above.

## 4. Demonstration sequence

1. Power the system and show the startup self-test. Wait for green LED and `NORMAL` on LCD/dashboard.
2. Show live temperature, humidity, acceleration, seal, GPS, module health, and the scrolling acceleration graph.
3. Press Button 2. Confirm red LED, buzzer, `MANUAL` on LCD/dashboard, a new timeline item, and event evidence on SD.
4. While the event is active, press Button 1. The buzzer stops immediately, but red remains on and the dashboard reports **acknowledged; evidence capture continues**.
5. After the post window, show automatic return to normal. Wait through the five-second cooldown before testing another automatic event.
6. Tap the package/MPU for IMPACT or SW-420 vibration, then remove the reed magnet for TAMPER. Restore the magnet before the next test.
7. Remove the SD card only while powered off. Open `EVENTS.CSV` and show approximately two seconds of `PRE`, one `TRIGGER`, and three seconds of `POST` evidence.

## 5. Configuration and recovery notes

- `PASSIVE_BUZZER 1` produces a non-blocking 1400/2200 Hz siren. Set it to `0` for an active buzzer. `BUZZER_ACTIVE_HIGH` controls active-buzzer polarity.
- Thresholds, timing, SW-420 polarity, LCD use, and buzzer type are grouped near the top of the sketch.
- DHT alarms use 2 °C / 5% hysteresis. Impact/vibration event extension preserves alarm acknowledgement.
- Missing MPU, RTC, DHT, LCD, GPS fix, or SD does not stop the main loop. MPU/RTC/SD are retried periodically; GPS distinguishes zero received bytes from received data without a fix.
- GPS-derived RTC synchronization happens once and uses UTC.
- Web Serial and Arduino Serial Monitor cannot own the same COM port simultaneously.
